## 1.4-snapshot6 · 2026-11-08 · 快照版

> 1.4 第六个快照：账户页的皮肤预览重做了。以前那张是贴在平面上的图案，只能正着看；现在皮肤贴到带厚度的立方体上，头、身体、四肢各自成块，拖着就能转着看侧面和背面。只要鼠标还在启动器窗口里，不管停在侧栏还是别的地方，头都会朝鼠标方向偏，移出窗口自己回正。这块预览也从上一次的「账户设置」弹窗搬到了账户页右侧 —— 点账户列表任意一行就换人，动作定成 5 个：走路、跑步、游泳、坐下、默认。

### 新增 · 皮肤预览换成真的 3D 立体

- **从平面变成方块**：以前是把贴图正面裁下来拼成一个平面小人，转视角就露馅；现在把 64×64 皮肤按六个面贴到立方体上 —— 头、身体、两条胳膊、两条腿各自成块，有厚度，侧面和背面都画得出来，帽子层与外套层也在
- **明暗跟着朝向走**：每个面按朝向算一层阴影，正面最亮、侧面渐暗、背面最暗，转动的时候能看出体积，不再是一张纸片
- **前后遮挡是对的**：六个面先投影再按深度从远到近画，手臂压在身体前面时不会被身体盖住，走动时两条腿也不会互相穿模
- **经典 / 苗条都认**：Steve 的 4px 手臂和 Alex 的 3px 手臂按账户的模型设置分开算宽度，苗条皮肤不会被画出宽肩膀

### 新增 · 头会跟着鼠标转

- **鼠标移到哪，头就朝哪**：不用把鼠标挪到预览区里 —— 只要还在启动器窗口里，左右移动头最多偏 46°，上下最多 26°，往下移是低头、往上移是抬头；鼠标离画布越远转得越多，到窗口边上就是上限
- **移出窗口自己回正**：鼠标离开启动器窗口（或窗口失焦）后，头会慢慢转回正前方，不会停在歪着的样子
- **转得是缓的**：每帧朝目标角度追 18%，鼠标甩得快也不会硬拐；按住拖动转视角时不抢方向，松手才继续跟鼠标

### 改进 · 预览从「账户设置」搬到账户页

- **不用点进去也看得见**：以前预览藏在某个账户的设置弹窗里，不点那一下根本不知道有这东西；现在账户页右侧固定有一块「当前账户皮肤预览」，打开就在
- **点列表就换人**：账户列表里点任意一行，右边立刻换成那个账户的皮肤，标题后面写着谁是「自定义皮肤」、谁还是默认皮肤
- **动作只留 5 个**：走路 / 跑步 / 游泳 / 坐下 / 默认，点一下即时切换，动画一直在跑 —— 按钮排成一行，不用再翻第二排
- **账户设置里的旧预览撤掉**：弹窗里不再重复摆一块画布，换肤看效果统一在账户页，不会出现两处动画各转各的

### 照顾 · 64×32 老皮肤仍走平面画法

- **64×32 老皮肤照旧能用**：这种格式只有正面贴图，硬套 3D 会像被削掉一半，所以仍用原来的平面画法，动作一样会动
- **动作少了，画法没退**：潜行、持物、穿甲这几套姿势的绘制代码仍在，只是先不给按钮 —— 以后想放回来，加一行动作就行
- **切走就停**：账户页切到别的页面后动画循环自己停下，不在后台一直重画
- **皮肤库缩略图不受影响**：库里的小方格仍是头像裁切，打开速度跟以前一样


## 1.4-snapshot5 · 2026-11-08 · 快照版

> 1.4 第五个快照：这一版全在修整合包导入。最要命的一条是下载会永久卡住 —— 数据早就收完了，可服务端不关连接，启动器就一直等，进度条永远停在「整合包文件 5/80」，现在本段收满立刻走、真停滞 25 秒就掐断重试；同时把 Fabric / Quilt 的加载器 jar 换成国内镜像，以前直连官方 maven 只有约 1KB/s，一个整合包光加载器就要等十几分钟。另外，整合包声明的加载器版本不再被忽略、PCL 勾了「打包启动器」的包能认了、CurseForge 整合包的配置不再写进游戏根目录、每个文件按索引里的 sha1 校验，中文包名也不会再显示成「PCL_」。

### 修复 · 整合包下载卡在某个文件上不动

- **症状**：装到某个文件就再也不动 —— 磁盘上临时文件的字节数已经和索引写的大小完全一样，等十几分钟零增长、也不报错，只能强杀。原因是服务端把数据发完了却不关连接，启动器一直在等「传输结束」的信号
- **本段收满就走**：分段下载现在按「这一段应有的字节数」判断，收满立刻跳出读循环，不再等服务端 close / FIN
- **真停滞会自己断**：每段 25 秒收不到任何字节就掐断这条连接，带 Range 从断点续传重试；连续两次停滞就交给单流兜底 —— 不会再出现「永远停在 5/80」
- 这个函数还负责客户端 jar、Forge 安装器与 CurseForge 下载，这几条链路一起修好了

### 修复 · Fabric / Quilt 整合包在国内装不上

- **加载器 jar 换镜像**：Fabric / Quilt 的加载器本体，以及 sponge-mixin、asm 这批依赖，以前写死官方 maven —— 境内实测只有约 1KB/s，34KB 要等 40 秒；现在自动走 BMCLAPI 镜像，同一批 jar 4 秒下完
- **换源也生效**：设置里把下载源切到 BMCLAPI 时，加载器 maven 也一起换（以前只换 Mojang 那几个域名，切了源也照样卡）
- 镜像拿到的文件一样按 sha1 校验，内容不对不会落盘

### 修复 · 整合包装出来跟包里写的不一样

- **加载器版本不再被忽略**：包里声明 fabric-loader 0.19.5，以前装出来是 0.20.1（mod 按旧版编译的会直接崩，而且整合包安装不经过版本下拉，用户没法补救）；现在按包内版本装，只有上游确实下架了才退回最新并明确提示
- **「打包启动器」的包能认了**：PCL 导出时勾了这一项，外层 zip 里只套着一个 modpack.mrpack；以前三个索引探测全落空、直接报「无法识别的整合包格式」，现在先取出内层再按整合包安装
- **CurseForge 整合包的配置不再撒在游戏根目录**：overrides 改到实例自己的目录，两个整合包不会互相覆盖，实例也会被正确判为「版本隔离」；重名实例同样有友好提示
- **每个文件按索引 sha1 校验**：索引里本来就写着 hashes.sha1，以前这条链全程不比对，坏 jar 会静默落盘、等到启动崩溃才发现；现在不符就删掉重下，日志里写清是哪个文件

### 改进 · 中文包名与进度看得懂了

- **中文包名不再变成下划线**：目录名仍用 ASCII（避免编码问题），但界面显示包里原本的名字 —— 「PCL导出包测试」不再显示成「PCL_」，实例页、版本下拉、主页版本按钮统一
- **进度不再把资源包算成 MOD**：文案从「整合包文件 5/80」变成「5/80（mod 65 · 资源包 13 · 光影 2）」，装完的提示也只报真正的 MOD 数

### 修复 · 导入整合包时右下角浮窗不出进度

- **症状**：点「导入整合包」后右下角那个浮窗要么一直停在 100%「安装完成」不动，要么干脆不出现 —— 其实文件还在往磁盘里写，只是界面看不到；换成 GB 级的包，那段时间能有好几分钟
- **根因有两处**：一是还原包内文件时把整包一次性同步解压，主进程被占住，进度事件全堵在队列里发不出去；二是进度分三段各自从 0 走到 100%（装游戏本体 / 下包内文件 / 还原文件），后一段一开始就掉回个位数，看着像卡死又复活
- **改成一条不回头的整体进度**：读包 0~6% → 装游戏本体与加载器 6~70% → 还原包内文件 70~99% → 100%，百分比只许前进；还原阶段逐个文件读、每个之间让出主线程，浮窗跟着动
- **每个阶段都有话说**：读盘显示「读取 xxx.mrpack（128.0 MB / 460.0 MB）」，还原显示「还原包内文件 128/800」，包内文件按字节推进 —— 一个 200MB 的大 mod 也不会卡在同一个数字上
- **浮窗标题与完成文案跟着任务走**：导入显示「导入整合包 / ✓ 导入完成」，下载页装整合包显示「安装整合包」，普通下载仍是「下载任务 / ✓ 下载完成」

### 修复 · 浮窗不关，还会把下一次下载标成「导入失败」

- **症状**：整合包导入完成后，右下角浮窗偶尔一直挂着不消失；这时候去下载游戏、中途点「停止安装」，浮窗却说「已取消导入」甚至「✗ 导入失败」—— 看着像整合包导入坏了，其实两件事没关系
- **根因**：负责收尾的「完成」标记被一条迟到的进度事件清掉、顺手把浮窗重新建了一个 —— 新建的这个再没有人负责结束，于是永远留在屏幕上；它身上还带着上一次任务的「导入」标签，下一次下载就直接沿用了这个标签
- **收尾后不再接受迟到的进度**：已经结束的任务，后面再来进度事件一律忽略；每个任务在开始时（下载游戏 / 装整合包 / 导入 / 自定义下载）显式开新任务，标题、类型、百分比全部归零 —— 停止下载只会说「已取消下载」
- **兜底自愈**：浮窗走到 100% 之后 8 秒还没收到结束信号，就自己收掉，不会再出现「关不掉的窗」
- **结束态的浮窗点一下立刻收掉**，不用等 4 秒淡出

### 移除 · 极速模式与左下角的小圆圈

- **极速模式整块去掉了**：以前按住左下角小圆圈满 10 秒可以切换的「极速模式」（按住时圆圈转出进度环、字母从 L 变 S、圆圈变琥珀色，界面动画与过渡全部压到瞬间完成）不再提供，相关配置项一并移除 —— 动画与过渡保持正常速度，界面看起来和以前没开极速模式时一样
- **左下角那个小圆圈也删了**：侧栏底部那个跟着账户首字母变化的圆形字母（长按切极速的入口就藏在它身上）整块移除，侧栏现在只剩顶部的启动器图标与一排导航按钮；账户的查看与切换仍在左侧「账户」页
- **老配置不受影响**：以前开过极速模式的机器上，配置里还留着那条旧字段，现在读取时直接忽略 —— 启动器不会因此报错，也不会再悄悄把界面切成省电形态

## 1.4-snapshot4 · 2026-11-07 · 快照版

> 1.4 第四个快照：下载页的皮肤不再只认正版 —— 新增「皮肤站 / 正版档案 / 本地文件」三种来源，离线账户也能直接搜皮肤站的作品、拖本地 PNG 换肤；同时给皮肤库补上两处安全收口，按 URL 导入会拦掉内网 / 回环地址，改名补上与删除同款的路径校验。

### 新增 · 下载页皮肤不再只认正版

- **三种来源**：皮肤分类顶部可切「皮肤站 / 正版档案 / 本地文件」，默认打开皮肤站 —— 离线账户也能直接换皮肤，不再被「正版里查不到这个名字」挡在门外
- **皮肤站**：接 LittleSkin 公开皮肤库，搜作品名或作者名（中文也能搜），可切最新 / 热门，往下滚到底自动加载下一页；每张卡片直接显示穿在身上的效果、作者和点赞数
- **本地文件**：把 PNG 拖进虚线框、点「选择文件…」、或粘贴图片直链都行；128×128 / 256×256 的 HD 皮肤按最近邻缩到 64（不会糊），64×32 的老皮肤也认，尺寸不合规直接拒收
- **修复导入不显示**：账户设置 → 皮肤库里导入与账户正在用皮肤同内容的图片时，以前会提示「已导入」但列表里永远不出现（去重误把账户私有副本当库条目）—— 现在正常入库并立刻显示
- **套用即生效**：预览卡上的模型标签可点，随时在经典（Steve）和苗条（Alex）之间切；「存库」收进皮肤库，「套用」直接给当前账户 —— 离线账户启动时会注入本地皮肤服务器，游戏里真能看到

### 安全 · 按 URL 导入皮肤拦内网地址

- **拦回环与内网**：按 URL 导入皮肤现在会拒绝 127.0.0.1、localhost、10.x / 172.16-31 / 192.168.x、169.254.x 等内网与云元数据地址，只放行公网直链 —— 避免「按 URL 导入」被当成探测内网服务的跳板
- **尺寸与大小照旧**：仍是 64×64 / 64×32 的 PNG 才收、超过 2MB 拒收，这一层没有放宽

### 安全 · 皮肤库改名补路径校验

- **先查文件名合法性**：改名现在和删除 / 套用一样，先拒掉带 `../` 的越界文件名，改不到皮肤库外面的文件
- **渲染层被污染也安全**：即使界面被注入、传进越界文件名，主进程这一层也会拦下

### 改进 · 测试口径与功能下架对齐

- 「下载游戏」默认下架后，版本列表整体不渲染，其「置顶区」测试改判为跳过 —— 不再把「本来就没有列表」误报成产品缺陷
- 皮肤库测试新增两条：改名拒绝越界文件名、URL 导入拒绝内网地址，钉住上面两处收口


## 1.4-snapshot3 · 2026-11-07 · 快照版

> 1.4 第三个快照：下载页多了「皮肤」分类，能按正版玩家名抓 Mojang 官方皮肤；账户设置里多了皮肤库和会动的预览（站立 / 行走 / 奔跑 / 潜行 / 持物 / 穿甲）；顺手修掉存档区块预览「永远是个正方形」的老毛病 —— 长条地形以后按真实比例显示，不再被压扁。

### 新增 · 下载页「皮肤」分类

- 按正版玩家名查：名字 → UUID → 官方档案 → 皮肤直链，只走 Mojang 官方接口。正版里没有的名字会明确提示（离线账户本来就没有公开皮肤）
- 先存库再套用：结果卡上带动作预览、UUID 与文件大小，一个按钮存进皮肤库、另一个直接套给当前账户；下面还有 6 个推荐玩家，点一下就能查
- 只收真皮肤：64×64（新版）与 64×32（旧版）之外的图在导入时就被拒 —— 128×128 之类的图进游戏根本不生效，不如当场说清楚

### 新增 · 账户设置：皮肤库 + 动作预览

- 预览会动了：原来只有一张静止贴图，现在是个会动的小人 —— 站立有呼吸、行走摆臂、奔跑加速、潜行弓身、双手托着方块、整套盔甲上身，六个动作随点随换
- 皮肤库：账户设置里列出本机所有皮肤（头像 + 名字 + 模型），点一格就套给这个账户；正在用的那格有描边和「使用中」，删除别人正在用的会被拦下并说是谁在用
- 套用是复制一份：不共享文件，换皮肤 / 删账户都不会动到库里的原件；同一张图重复导入按内容去重，库里不会出现两条一模一样的
- 在线账户不显示皮肤库：微软 / 外置登录账户的皮肤由认证服务器下发，本地换了也不生效，干脆不摆这块区域

### 修复 · 存档区块预览只能画成正方形

- 根因：预览窗口固定按 32×32 区块取，长条或形状不规则的存档被硬塞进正方形，比例完全失真 —— 1×40 的峡谷也会变成一张方图
- 改按真实长宽比算窗口：先取已加载区块的包围盒，再按面积预算（最多 1200 区块、单边最多 48）等比缩放，1×40 的存档出 48×2，60×3 的存档也不会被压扁
- 顺带裁掉空白边：四周解析不出数据的行 / 列会被裁掉（比如某个 region 只剩表头、扇区指向文件外），图里不再有大片未加载底色
- 小存档行为不变：规规矩矩的 2×2 世界仍然出 32×32
- 新增 `qa/e2e-mappreview.js`：长条 / 超长条 / 边缘破损 / 小方块四个夹具钉住比例、裁剪与老行为

### 修复 · 皮肤预览与界面细节

- 行走 / 奔跑重画：正面 2D 视角改成「一条腿向外迈出、另一条收起抬高 + 对侧摆臂」，不再出现两腿交叉成 X、双臂外张像投降的样子；持物改成双手在胸前托着方块，穿甲贴片贴合身体
- 修掉两处启动期崩溃：新皮肤页与账户弹窗的初始化顺序会让整页脚本报错，现在页面与弹窗都能正常打开
- 皮肤库细节：改名静默失效、套用后库里多出重复条目、在线账户仍显示皮肤库等问题一并处理；移除皮肤时同步清理元数据
- 更新公告瘦身：弹窗只显示当前版本，24 条历史公告原文归档到 `docs/CHANGELOG-history.md`，不再逐版堆在启动器里

## 1.4-snapshot2 · 2026-11-06 · 快照版

## 1.3-snapshot2 · 2026-10-29 · 1.3 快照版

> 这一版没有新功能，全部在修「出问题时让你更安全」的细节：配置保存改成原子写（断电 / 磁盘满不会再让设置整份丢失，坏掉的配置会自动留一份备份）、关启动器时会等「退出后自动备份」跑完、正版账户启动不再误报「离线模式」、启动前命令不会被实例名里的特殊字符注入、开服同步模组能认出「同体积但内容不同」的文件、删除 MOD 改走回收站。

### 修复 · 设置不再可能整份丢失

- 保存改成原子写：先写临时文件、刷盘、再改名覆盖。以前直接覆盖原文件，写到一半断电 / 进程被杀 / 磁盘满就会留下半截 JSON
- 坏配置自动留档：如果下次启动发现配置解析不了，会把原文件改名成 `lmc.config.json.bad-<时间戳>` 留着，再用默认值启动，并在界面上告诉你 —— 以前是静默用默认值，原始内容还会被下一次保存覆盖
- 保存失败会说：磁盘满 / 文件被占用时，日志和界面都会明确提示「设置保存失败」，不再显示已保存却什么都没落盘

### 修复 · 关启动器不再吞掉「退出后自动备份」

- 关掉游戏后 2.5 秒内顺手关掉启动器，以前这次备份根本不会开始（定时器随进程一起消失）
- 现在退出前会先把它触发并等它跑完；备份正在写 zip 时关启动器也会等最多 3 秒，超时才放弃并写日志

### 修复 · 启动成功的提示按登录方式显示

- 以前不管用什么账户都弹「游戏进程已启动（离线模式）」，正版玩家会以为登录失败、掉到离线了
- 现在按实际情况显示「微软正版登录 / 外置登录 / 离线模式」

### 安全 · 启动前命令不再被实例名注入

- `${gameDir}` / `${version}` 的取值来自游戏路径和实例名，导入整合包时实例名可能含 `& | < > ^ %` 这类 shell 特殊字符
- 含这些字符时跳过这条可选脚本并在日志 / 界面说明原因，不再把它拼进命令行执行

### 修复 · 开服「同步模组」更准、失败可见

- 以前只比文件体积：体积相同但内容不同的 jar（换过构建 / 被替换过）会被判成「已同步」；现在按体积 + 修改时间判断，并在拷贝后对齐时间戳，避免每次都重拷
- 单个 mod 复制失败不再静默跳过：同步结果里会给出失败清单和数量

### 修复 · 删除 MOD 改走回收站

- 和存档 / 实例删除保持一致：先移入系统回收站，回收站不可用才退化为直接删除 —— 误删自己改过的 jar 还能捞回来

### 修复 · 反馈页会翻页，条数不再虚报

- Issue 超过 100 条后，更早的条目以前会静默消失、页面上的「共 N 条」也只是本页条数
- 现在顺着分页拉取（最多 5 页），还有更多没取时显示「已加载最近 N 条」并提示去 GitHub 看全部

### 修复 · 模组清单截断会说明

- 超过 600 个模组时清单只列前 600 个，以前没有任何提示，两边都少了同一批时可能显示「完全一致」
- 现在截断时清单里会加一行说明，比对结论也会标注「清单已截断，之外的未比对」

- 右摇杆上下 = 鼠标滚轮：轻推慢慢滚、推到底快速翻长列表，滚的是指针底下那个容器，指哪滚哪（轻推能停在想看的位置）

### 新增 · 主页按钮两副面孔：游戏跑起来就变「关闭游戏」（▶ → ■）

- 主页那个大圆按钮现在有两副面孔：待机时是 ▶「启动游戏」，游戏真的跑起来后同一位置换成 ■「关闭游戏」—— 跟视频播放器的开始 / 停止一样，点一下就关掉游戏，不用再去任务管理器里找 java.exe
- 「运行中」的判定来自主进程（游戏进程真的拉起来了才算），不是界面自己猜的；启动准备阶段（下 Java / 校验文件）按钮保持禁用，避免连点双开
- 「关闭游戏」收的是整棵进程树：游戏本体是 java.exe，模组 / 启动参数可能再分出子进程，只杀父进程会留下一堆孤儿进程继续吃内存

### 修复 · NeoForge：检测与安装不再自相矛盾

- 修掉「NeoForge 明明有构建却报不兼容」：NeoForge 官方源在国内时常连不上、回 502，而它的镜像（BMCLAPI）现在要先跳一次对象存储，实测同一台机器上 1 秒到 15 秒都可能；原来给镜像只留了 10 秒，两边一起慢的时候就会误报「构建信息获取失败」，界面上直接显示成「✗ NeoForge 与 xxx 不兼容」，把人吓退。现在镜像留足 20 秒，而且真查不到的时候改成「⚠ 未能确认 + 重新检测」（与 Quilt 那套一致），不再把网络问题说成不支持
- 修掉 1.20.1 上 NeoForge 的错判：1.20.1 的 NeoForge 用的是旧坐标（版本号形如 1.20.1-47.1.106），而原来的前缀推导算出的是「20.1.」，跟任何一条版本都对不上 —— 结果 1.20.1 明明有 62 个构建，界面上却是「✗ 不兼容」、装不了。现在 1.20.1 能正常检测并安装 NeoForge（最热门的模组版本，这个修复很关键）
- 修掉新版本号（26.x）装不上 NeoForge：安装器原来按「1.x.y」的格式解析版本号，遇到 26.3 这种没有「1.」前缀的新编号会直接报「无法解析版本号」—— 检测说兼容、安装却失败。现在安装与检测统一走同一套前缀规则
- NeoForge 只发布了预发布版时，不再出现「检测说兼容、安装说没有正式构建」：优先装正式版，确实一个正式版都没有（例如 26.3 目前只有 -beta）就装最新的预发布版，与 OptiFine「正式版优先、没有则用预览版」保持同一策略
- Forge / OptiFine 的构建查询也一并区分「查不到」与「确实没有」：网络慢不再被当成不兼容

### 改进 · 下载页：最新正式版与预览版置顶

- 「下载游戏」的版本列表最上面现在固定一个「置顶」区，同时给出当前最新正式版与当前最新预览版（快照 / 预发布 / 候选版）—— 不用在「正式版 / 快照版」几个标签间来回切，一眼就知道现在最新的是什么
- 置顶的两条取自版本清单自带的官方标注（Mojang 的 latest.release 与 latest.snapshot），不是按发布日期自己猜，所以不会出现「预发布版被当成正式版」这类错位
- 置顶区里的版本不会在下面再重复出现一次；搜索时会自动收起置顶区 —— 否则「明明没匹配到，顶上却还挂着两条」会让人误以为搜索没生效
- 「远古版本」标签下不置顶：那个页面本来就是专门翻 b1.7.3 这类老版本的，顶上塞个 26.3 只会添乱
- 下载页默认选中的分类改成「全部」：以前默认停在「正式版」，想装个快照 / 预览版还得先手动切标签；现在一进来就是全部版本，置顶区仍然把最新正式版与最新预览版单独拎在最上面

### 新增 · 光影下载：Modrinth / CurseForge 两源搜索，一键装进 shaderpacks

- 「下载」页多了一个「光影」标签：从 Modrinth 与 CurseForge 两个源搜索光影包（可切单源，或「综合」两源合并按下载量排序），点「安装光影」直接装进游戏目录的 shaderpacks，不用再自己去论坛和网盘里翻压缩包
- 可以指定装给哪个实例：选具体实例就装进那个实例的光影目录（版本隔离实例读的是实例目录里的 shaderpacks，装对位置游戏里才看得到）；选「全部」则放进游戏根目录，所有实例共用
- 面板顶部会写清这次到底装到哪个目录，并提醒光影需要 Iris 或 OptiFine 才能在游戏内选中生效；若选中的实例是原版（没有模组加载器），会明确告诉你「只装光影不会生效，还得先装 Iris / OptiFine」，省得装完一脸问号
- 详情页里能挑具体版本：列出该光影适配的各版本文件（带 MC 版本与体积），装的就是你点的那一条，不是「悄悄给你最新版」

- 搜索支持中文：输入「光影」「着色器」就能搜到，不用先想英文名

### 修复 · 版本号判定：装了新快照，不会再被劝「更新」到旧正式版

- 修掉「明明是更新的版本却说旧版才是最新」：版本号比较原来把所有预发布 / 快照一律归进「0 系列」，于是任何正式版都排在它们前面 —— 装了 1.1-snapshot1 的用户会被劝去「更新」到更旧的 1.0。现在改成按「目标版本 + 阶段」两段比：1.1-snapshot1 比 1.0 新，但仍比正式版 1.1 旧（同为 1.1，正式版盖过快照）
- 早期那种「关键字写在最前」的老写法（Beta1.0 / Pre1 / RC1）仍按 0 系列处理，正式版照样能盖过它们 —— 老预发布用户不会因此收不到正式版更新
- 版本号比较补了离线自测（含 1.1-snapshot1 与 1.0 / 1.1 的对照用例），以后调版本规则不会再悄悄改坏更新判定

### 新增 · 版本更新：可以「跳过快照版更新」，主页提示快照版风险

- 「设置 → 版本更新」里多了一个开关「跳过快照版更新（只接受正式版更新）」：开启后，更新源上出现的是快照 / 预发布 / 候选版时不提示更新，只有正式版才会提示。默认关闭 = 照旧都提示
- 开着的时候检测结果不会含糊地写成「已是最新版本」，而是明确告诉你「更新源上的 1.1-snapshot2 是快照版，已按设置跳过」—— 开关一改会自动重新检测一次，想装随时关掉开关即可
- 主页顶部新增一行快照版提示：当前跑的版本是快照 / 预发布版时，顶部会写明「快照版可能包含未稳定的改动、可能出现严重 BUG」，并提示前往抖音主页反馈群反馈 —— 那行字里的反馈入口可以直接点，点一下就在浏览器里打开抖音主页；附上诊断日志能更快定位。正式版不会有这一行，省得让人误会
- 判定用的是与更新检测同一套版本阶段规则，不存在「更新里跳过了、主页却还提示快照」这种前后打架的情况

### 新增 · 版本回退：可以回到任意历史版本

- 「设置 → 版本更新」里新增「版本回退」区：把官方下载页上还挂着的历史版本（1.0、RC 1、Pre 1、Beta 1.0 这些）逐个列出来，每个都标明是正式版还是快照 / 预发布，想回哪一版就点哪一版（下的是免安装的便携版 exe，不需要跑安装向导）
- 回退走的是「覆盖」而不是「安装」：启动器内下载那一版的便携版 exe → 点「替换并重启」，它会把当前的启动器程序文件换成这一版再自动打开，就算回到那一版了。游戏目录、存档、设置与账户都不会动；回退以后想再更新回来，点一下「检测更新」就行
- 当前跑的正是快照版时，回退区会额外给出「回到稳定版」的提示卡，一键回退到最新正式版 —— 配合「跳过快照版更新」，就能稳稳待在正式版上
- 回退区只列比当前旧的版本（正在用的这一版会标出来，但不给回退按钮）；已经是最老的版本时，这一区自动隐藏

### 改进 · 智能内存分配：改成 PCL 式算法，按「实例需要多少 + 系统还剩多少」来发

- 智能内存分配换了算法：以前是「看物理内存总量查表」—— 8 GB 给 4 GB、16 GB 给 6 GB 这样一刀切，完全不看你要启动的实例装了多少模组，几十个模组的整合包和空的原版给得一样多。现在分两段算：先看这个实例需要多少（按启用的模组数量推出「起步 / 舒适 / 充裕」三个目标值，原版与装了 OptiFine 的另有基准），再看此刻系统真正剩多少可用内存分四档发 —— 需求在「起步」以内全给，往上是 70%、40%，再多只给 15%，既够用又不会把系统挤爆
- 模组数量按这个实例自己的 mods 目录数（版本隔离的实例只算它自己的，再并上全局 mods 目录，同名只算一次）；只数启用的 `.jar / .zip / .litemod`，被改名成 `.jar.disabled` 的停用模组不计入，模组形态安装的 OptiFine 也认得（装了它基准值抬高一档）；因此原版给得少、几百个模组的整合包给得多
- 用 32 位 Java 启动时一律压到 1 GB —— 32 位 JVM 本来就寻址不到更大的堆，给再多也起不来（会直接报「Could not reserve enough space」）
- 兜底规则：无论如何不低于 1 GB，上限取「物理内存 - 1 GB」（给系统留余量）且不超过 64 GB，再向下取整 —— `-Xmx` 只认整数
- 「游戏设置 → 内存」的提示改了：不再只写「物理内存 N GB」，而是写清这台机器有多少、此刻还剩多少、这个实例有多少个模组、据此推荐多少，鼠标悬停能看到四个目标值与分档规则，推荐值是怎么算出来的一目了然
- 手动滑块的上下限跟着物理内存走：以前写死 2~16 GB，32 GB 的机器想把内存拖到 16 以上都拖不动；现在上限按物理内存算，机器够大就能给到位。换「默认实例」时会立刻按新实例重算一遍推荐值

### 修复 · 一轮全面自检后的整改：内存 / 跨平台 / 下载稳定性

- 修掉「内存填大数游戏反而起不来、还看不出原因」：此前内存只有下限、没有上限，设置里填 999（GB）会被原样写进 Java 参数（-Xmx999G），游戏启动即失败、报错却和「内存设置」毫无关系，很难自查。现在内存值统一钳制 —— 下限 1 GB、上限取「64 GB 与物理内存中较小者」，填多大都只会落到这台机器扛得住的范围里
- 修掉 classpath 分隔符被写死成分号：Java 的类路径在 Windows 上用「;」分隔，Linux / macOS 上是「:」。写死分号会让整条类路径在非 Windows 系统上被当成一个路径 —— 一个库都找不到、游戏直接起不来。现在按运行平台自动选择分隔符（这项也正是那轮 50 项机械审计里唯一没通过的一项，现已修复）
- 修掉「下载写到一半卡死」：磁盘写满、没有写入权限、目标文件被别的程序占用这类情况，此前下载的写入流没有任何错误兜底 —— 界面表现为进度条永久卡住，既不出错也不结束（看着就是「卡死」）。现在写入一旦失败会立刻结束这次下载、把原因报出来，并照常清理没写完的临时文件，重试即可
- 修掉「联机」页反复点「下载组件」会持续堆积监听（内存泄漏）：此前每点一次「下载」就多挂一个永不解绑的进度监听，点得越多堆得越多；现在下载一结束立刻解绑，与「一键开服」里同一段逻辑保持一致
- 加固 ZIP 解压：包内条目名带「../」时可能被写到目标目录之外（zip-slip）。现在解压前先把条目路径规范化，越界条目直接跳过 —— 解压 natives 与整合包导入/导出工具里的同类解压都用上了这同一道校验
- 加固版本目录名校验：启动游戏、查看版本信息时传入的版本名必须是纯名字，带「../」这类路径形态的会被直接拒绝，杜绝越过游戏目录去读别的文件（与删除 / 重命名实例的校验保持一致）
- 收紧「打开所在文件夹」的范围：只允许打开游戏目录与启动器数据目录里的路径，其他位置即使被传入也不会交给系统打开 —— 与外部链接的协议白名单是同一个思路
- 以上整改来自一轮全面自检（50 项机械审计 + 多轮人工代码审查）：50 项审计 49 项通过（唯一没通过的正是上面的跨平台分隔符，已修），审查未发现高危问题；同时复核确认了一批本就扎实的地方（命令调用全部走参数数组、界面输出统一转义、下载原子写入与完整性校验、取消检查点、启动防重入锁等）。这一轮主要是把这些边角补齐

- 实测：选中加载器的检测结论约 0.1 秒就能显示出来（以前是几秒到十几秒），选好加载器马上就能点「开始安装」

- 仍然保持你要求的行为：不缓存旧结论，每次打开安装弹窗都会重新向官方源查一遍，加载器发布新构建后不用等启动器更新就能立刻装上

- 「一键开服」插件：支持 Paper（推荐）/ Purpur / 原版 / Fabric 四种服务端核心，自动拉取该核心的可用版本列表，选好核心与版本即可
- 填好服务器名称、内存、端口、MOTD、难度、游戏模式、正版验证后点「创建服务器」：自动下载服务端（带进度条与完整性校验），并生成 eula.txt、server.properties、start.bat 与服务器信息文件，参数都按你的设置写好
- 开服后内置控制台：实时显示服务器日志，可以直接在输入框里执行服务器命令（say、op、stop 等）；一键停止会先让服务器保存世界再退出，不会丢档；还支持打开服务器目录、删除服务器（移入回收站）
- 自动匹配 Java 版本：按所选服务端版本挑选满足要求的最低 Java 运行时（如 1.17 需 Java 16、1.18-1.20.4 需 17、1.20.5 以上需 21），找不到会提示，不用手动改参数
